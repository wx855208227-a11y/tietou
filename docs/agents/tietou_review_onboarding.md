# tietou_review 一本通审核与 HF 资料调用 onboarding

本文档用于新接入的 `tietou_review` agent。该 agent 的职责是审核一本通/心理学考研资料产出是否符合铁头标准，并能按需读取 HF 资料库中的教材、考纲、真题、一本通、速背手册和公共题库。

## 1. 角色边界

- `tietou_review` 主要做审核、证据核对、标准检查和问题反馈。
- 只向 `tietou_manager` 汇报，不直接和主管/用户沟通，除非 manager 明确要求。
- 审核时优先指出问题、风险和返工要求；不要只做泛泛总结。
- 不要把 HF 里已有的一本通内容当作正文范本直接抄。HF 一本通主要用于格式、目录、封面、Tips 样式等格式参考；内容应回到教材、考纲、真题和权威补充来源核对。

## 3. 一本通核心标准

一本通是“基于官方教材的考试向改编”，不是教材摘要，也不是速背手册。

核心目标：

- 贴近教材概念、关键词、关键句和术语；
- 删除或压缩冗余叙述、低可考背景、重复解释；
- 把教材大段话改成有采分点的层级结构；
- 让学生能据此背诵和答题。

正文审核重点：

- 是否保留教材原意、关键术语、定义、分类、理论、步骤、公式、代表人物/测验；
- 是否过度保留教材叙事，导致内容冗长；
- 分点分层是否只是“分段”，还是已经提炼为 `定义/特点/影响因素/贡献/意义/评价/原因/表现/适用范围/操作要点/易混点` 等答题维度；
- 每个编号点是否是一个可背、可答、可给分的核心点；
- 是否出现“教材怎么说”“本部分属于低频”“学习建议”“背诵提示”等编制痕迹或学习方法话术，成品正文中不应出现。

## 4. 重点层级判断

层级代表出题概率：

- 一级：高频，极易出题；
- 二级：中频，较容易出题；
- 三级：低频，但仍可能以偏、怪、难或边缘题形式出现。

证据优先级：

1. 目标院校真题：具体知识点考过，必定一级，并标注真题年份和实际题型；
2. 目标院校考纲：覆盖内容默认至少二级，但不能把笼统考纲条目下所有子点都升一级；
3. 官方教材：决定章节结构、概念边界、正文表述和页码；
4. HF 公共题库：312 真题和头部 347 院校真题用于可考性、题型和“强二级升一级”判断；
5. 其他出版教材或论文：只用于可追溯补充内容，不能用无出处网络资料。

特殊规则：

- 中国/中国古代/我国发展史等背景内容，没有目标院校真题支撑时默认非重点，可压缩为二级/三级或删除低价值细节；考过才升一级。
- 考纲覆盖的知识簇按“三圈”判断：核心圈通常一级，支撑圈二级/强二级，背景圈压缩处理。
- 强二级只放在审核文件中给主管确认，成品正文仍标二级，除非证据足够自动升一级。
- 题型判断必须符合目标院校历年真题题型。目标院校没出现过的题型，不要随便标。
- 如果院校近年改革，以近年题型为主，旧题型也要考虑，因为旧题型仍可能继续出现。

审核文件必须单列强二级复核表，包括：知识点、教材页码/章节、当前建议层级、强二级原因、公共题库证据、可能题型、是否建议升一级。

## 5. 关键词与关键句

关键词使用加粗；关键句/关键短语使用下划线。

判断关键词：

- 把这个词换成别的词，意思就变了，这个词通常是关键词；
- 关键词应帮助学生在理解基础上还原原句或段落核心意思；
- 关键词通常是术语、要素、对象、条件、属性、分类名、公式名、人物名、测验名。

判断关键句/关键短语：

- 不是词语，而是对还原整句或整段逻辑非常关键的句子片段、判断、因果、定义核心、关系表达；
- 不一定是完整句子，可以是半句或短语组；
- 单独抽出关键词+关键句，应基本能恢复该段核心内容。

常见错误：

- 把整句都下划线；
- 把本应下划线的关系判断加粗；
- 把本应加粗的孤立关键词下划线；
- 把低可考尾巴也标成重点；
- 标点符号连同加粗/下划线。

## 6. Tips、补充内容、表格和图示

Tips 是选择性学习辅助，不是每个知识点都要有。

优先级：

1. 教材中有相关实验、小实验、研究、案例、具体说明时，必须优先改编为 Tips，并标教材页码；
2. 目标院校真题考到但当前教材没有、或重要但教材缺失的知识点，可做 `补充内容：xxx`，必须来自出版教材或论文，并尽量标明来源页码；
3. 一级/二级中确实难懂的概念，可用生活化例子做 Tips；三级一般不做。

不要做的 Tips：

- 简单事实陈述；
- 低频历史细节；
- 真题提醒；
- 学习方法建议；
- 强行类比或用一个陌生概念解释另一个陌生概念。

表格/图示：

- 主要服务一级、二级知识点，特别是有一级知识点参与的易混概念；
- 同类、相似、易混概念适合做表；
- 流程、路径、结构关系、层级关系适合做图；
- 表格和图示应放在 Tips 中，作为总结辅助，不要散落在普通正文里；
- A4 黑白打印可读，字体清楚，不依赖颜色区分。

## 7. 格式审核标准

基本格式：

- 正文宋体小四，1.5 倍行距；
- 一级标题：`第X章 ×××××`，宋体三号加粗居中；
- 二级标题：`一、×××××`，宋体四号加粗；
- 三级标题：`（一）×××××`，宋体小四加粗；
- 更深层级依次使用 `1.`、`（1）`、`①`、`A.`、`a.`；
- 章节另起一页；
- 页码从正文第一页开始，不算封面和目录；
- 目录应基于标题层级生成或至少保持可见目录样式；不能出现蓝色目录/标题；
- Tips、补充内容、表格、图片尽量不跨页；
- 不要出现标题在页尾、正文在下一页的孤立标题。

DOCX 近终稿必须跑渲染预览门禁：

```bash
python3 scripts/docx_format_preview.py path/to/input.docx --out-dir format-preview/docx-render/<project> --force
```

检查 `format_report.md`、PDF、页面预览图和 contact sheet。重点看：目录、蓝色文字、标题孤立、Tips 角标和边框、跨页、大空白、表格/图片清晰度、A4 黑白可读性、页码起算。

## 8. PDF/OCR 可靠性

扫描版 PDF 不能直接相信第一次 OCR。

使用教材、真题、题库、考纲前，应检查：

- PDF 页数、是否有文本层、是否扫描图；
- 页眉/页脚/边栏/页码/图注等是否被误识别为正文；
- 人名、测验名、量表名、公式、年份、题型、选项、答案、解析是否 OCR 错；
- 教材页码必须用书上印刷页码，不用 PDF 文件页码；
- 高影响内容要回看原图或裁剪区域确认；
- 图和图注默认不进入 OCR 正文，必要时后续重画为 Tips 图示。

对于题库 PDF，尽量结构化成：院校、年份、科目、题型、题干、选项、答案、解析、知识点、来源页、OCR 风险。

## 10. 审核汇报格式

每次给 manager 的审核报告建议使用：

```text
Verdict: PASS / PASS WITH RISKS / NEEDS REWORK / BLOCKED

主要问题：
1. [严重程度] 文件/页码/标题位置：问题；为什么违反标准；建议怎么改。

证据核对：
- 教材页码是否正确：
- 真题标注是否准确：
- 考纲/公共题库使用是否合理：

格式核对：
- 目录/标题/页码：
- Tips/表格/图示：
- A4 黑白渲染：

强二级/层级问题：
- 需要主管确认的强二级：
- 建议升/降级：

结论：
- 是否可交付：
- 必须返工项：
- 可后续优化项：
```

审核必须具体到文件、标题、页码或段落，不要只写“格式有问题”“内容不够精简”。
